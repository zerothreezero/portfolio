# 0 3 0 — Bluesky Portfolio

Статичне портфоліо на HTML, CSS і JavaScript, підготовлене з `030_portfolio_bluesky_v15.html` для GitHub Pages. Публікації та зображення завантажуються з публічного API Bluesky без авторизації. Поточний профіль: `zerothreezero.bsky.social`.

Сайт не потребує npm, процесу збірки, бази даних чи власного сервера. Для завантаження робіт потрібен інтернет.

## Структура

```text
portfolio-bluesky/
├── index.html             # Розмітка сторінки, метадані, підключення ресурсів
├── assets/
│   ├── css/
│   │   └── styles.css     # Стилі, теми, адаптивність, анімації
│   └── js/
│       ├── browser.js     # Раннє визначення Firefox
│       └── app.js         # API Bluesky, галерея, фільтри, переклади, статистика
├── .nojekyll              # Публікація статичних файлів без обробки Jekyll
├── .gitignore
└── README.md
```

CSS і JavaScript винесено зі збереженням початкового порядку. Статичні `style`-атрибути частинок фону перенесено до класів `sunset-particle-*` у CSS. Динамічні стилі анімацій, як і раніше, встановлює JavaScript.

`browser.js` виконується у `<head>` перед стилями, а `app.js` — наприкінці `<body>`, коли розмітка вже доступна. Не додавайте `async`: порядок завантаження важливий. Шляхи `./assets/...` працюють і в корені домену, і в підкаталозі репозиторію GitHub Pages.

## Запуск локально

Відкрийте термінал у папці з `index.html`. Якщо встановлено Python 3, виконайте:

```bash
python -m http.server 8000 --bind 127.0.0.1
```

У Windows також можна використати `py -m http.server 8000 --bind 127.0.0.1`.

Відкрийте [локальний сайт](http://127.0.0.1:8000). Для зупинки сервера натисніть `Ctrl+C`. Можна використати інший статичний HTTP-сервер; локальне відкриття через `file://` не є основним способом перевірки.

## Публікація на GitHub Pages

1. Створіть репозиторій на GitHub, наприклад `portfolio`. Для простого безплатного розміщення використайте публічний репозиторій.
2. Завантажте **вміст** цієї папки в корінь репозиторію: `index.html`, `assets/`, `.nojekyll`, `.gitignore`, `README.md`. Не завантажуйте ZIP і не вкладайте все ще в одну папку `portfolio-bluesky/`.
3. Збережіть файли в гілці `main`.
4. Відкрийте **Settings → Pages → Build and deployment**.
5. У **Source** виберіть **Deploy from a branch**.
6. Виберіть гілку **main** і папку **/ (root)**, натисніть **Save**.
7. Дочекайтеся успішного розгортання. Посилання буде в **Settings → Pages**, а перебіг публікації — у вкладці **Actions**.

Для репозиторію `portfolio` адреса зазвичай має вигляд `https://YOUR_USERNAME.github.io/portfolio/`. Для репозиторію `YOUR_USERNAME.github.io` — `https://YOUR_USERNAME.github.io/`.

Офіційні інструкції: [створення GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site) та [вибір джерела публікації](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

### Завантаження через Git

Як альтернатива завантаженню через вебінтерфейс: створіть порожній репозиторій без початкового README, відкрийте термінал у папці проєкту та виконайте команди нижче. Замініть `YOUR_USERNAME` і `portfolio` своїми значеннями:

```bash
git init -b main
git add .
git commit -m "Prepare portfolio for GitHub Pages"
git remote add origin https://github.com/YOUR_USERNAME/portfolio.git
git push -u origin main
```

Потім увімкніть Pages за кроками вище. Для наступних оновлень:

```bash
git add .
git commit -m "Update portfolio"
git push
```

## Налаштування

Основні параметри містяться в `assets/js/app.js`. Знайдіть їх за назвою:

| Параметр | Поточне значення / призначення |
| --- | --- |
| `HANDLE` | `zerothreezero.bsky.social` — профіль Bluesky. Вказуйте актуальний handle малими літерами, без `@` та URL. |
| `API` | Адреса публічного API Bluesky; для звичайного використання змінювати не потрібно. |
| `MAX_PAGES` | `10` — максимум сторінок API по 100 записів. Це ліміт перегляду стрічки, а не гарантія 1000 робіт. |
| `STREAM_BATCH` | `32` — кількість робіт, що додаються до галереї за один крок. |
| `HIDDEN_POST_IDS` | `new Set([])` — ID публікацій, які слід виключити. |
| `TRANSLATIONS` | Тексти інтерфейсу шістьма мовами, включно з українською. |
| `SOFTWARE_ALIASES` | Відповідність хештегів назвам програм для малювання. |

Щоб приховати публікацію, додайте останню частину її адреси після `/post/`, наприклад `new Set(['POST_ID'])`.

Щоб українська була початковою мовою, змініть `let language='en';` на `let language='uk';`. Збережений вибір користувача має пріоритет над початковим значенням.

Назву вкладки, SEO-опис і Open Graph-метадані редагуйте в `index.html`. Видимі тексти з атрибутом `data-i18n` беруться з `TRANSLATIONS`, тому їх потрібно змінювати в `app.js`. Оформлення змінюйте у `assets/css/styles.css`: пізніші правила можуть перевизначати попередні, як у вихідному файлі.

## Як додавати роботи

Опублікуйте у вказаному профілі Bluesky допис із зображенням. Після перезавантаження сайту він може з’явитися в галереї в межах ліміту `MAX_PAGES`. Репости, відповіді та дописи без зображень не включаються.

Приклад тексту публікації:

```text
261102 - Evening sky
1h 25m 9212s
Невеликий етюд вечірнього неба.
#art #landscape #procreate
```

- `261102` — дата створення у форматі `YYMMDD`, тобто 2 листопада 2026 року.
- `1h 25m` — тривалість роботи, `9212s` — кількість штрихів; `s` тут означає штрихи, не секунди.
- `#landscape` стає тематичним тегом; `#procreate` розпізнається як програма.
- `#art` і `#digitalart` виключаються з тематичних тегів.

Статистика дат використовує код `YYMMDD`. Без нього робота все одно відображається, але не потрапляє до статистики відомих дат створення. Дублікати об’єднуються за кодом дати, а за його відсутності — за першим зображенням. Тому кілька різних робіт з однаковим кодом дати можуть об’єднатися — це наявна поведінка версії V15.

Мова, тема та розмір робіт зберігаються у `localStorage` браузера. Сам архів робіт не зберігається локально: сайт повторно отримує його з Bluesky.

## Типові проблеми

- **404 на GitHub Pages:** перевірте гілку `main`, джерело `/ (root)` та наявність `index.html` саме в корені репозиторію.
- **Немає стилів або логіки:** перевірте, що папка `assets/` завантажена повністю, а назви файлів і регістр літер збігаються з посиланнями в HTML.
- **Галерея порожня:** перевірте `HANDLE`, доступ до інтернету, наявність власних дописів із зображеннями та відповіді API у вкладках Console/Network інструментів розробника.
- **Бракує старих робіт:** збільште `MAX_PAGES`; це збільшить кількість мережевих запитів і час завантаження. За помилки API сайт може показати лише частину архіву.
- **Зміни ще не видно:** перевірте завершення розгортання у GitHub Actions і перезавантажте сторінку без кешу (`Ctrl+F5`).

Зображення залишаються на серверах Bluesky; цей проєкт не містить їхніх локальних копій. API-ключі та паролі для роботи сайту не потрібні.
