# 0 3 0 — портфоліо ілюстрацій

Галерея отримує роботи з профілю `zerothreezero.bsky.social` та накладає на них правки з `data/portfolio-content.json`. Публічний сайт працює на GitHub Pages, у тому числі коли Worker недоступний. Галерея, статистика та перегляд зображень доступні без входу. Сайт статичний, зі звичайними HTML, CSS та JavaScript.

## Перегляд локально

Із кореня репозиторію виконайте `node scripts/serve.mjs` і відкрийте [localhost:8000](http://localhost:8000). Потрібен Node.js 22 або новіший. Для зупинки натисніть Ctrl+C. Сервер віддає публічні файли сайту. Адреси ресурсів також працюють у підкаталозі `/portfolio/`.

- **Огляд** відкриває хронологію з кількістю робіт за роками й місяцями, колекції, вибрані роботи, випадкову роботу та порівняння. Фільтри поєднуються з пошуком, тегами та діапазоном дат. Колекції й вибрані з’являються, коли мають дані.
- **Колір.** Для наявного архіву готові палітри містяться в `data/palettes.json`. Фільтр одразу працює без Worker. Для нових робіт **Визначити кольори** аналізує мініатюри в браузері, до трьох одночасно. Якщо CDN обмежує CORS, налаштований Worker може прочитати мініатюру лише за CID для фіксованого DID автора. Адреса довільного сайту не приймається. Палітра, задана редактором, має пріоритет. Для оновлення статичного індексу локально потрібен Python із Pillow: `python scripts/build-palettes.py`. Скрипт записує лише значення кольорів.
- **У переглядачі** стрілки, горизонтальний жест і мініатюри перемикають зображення. Режим фокусу залишає роботу й навігацію. Esc закриває перегляд. «Копіювати посилання» зберігає ID роботи та кадру в адресі.
- **Меню •••** містить тему, мову, розмір робіт і очищення локального кешу. Повторний візит використовує кеш метаданих Bluesky строком до семи днів під час оновлення. Зображення в повній роздільності підвантажуються під час перегляду.

## Перше налаштування онлайн

Потрібні публічний репозиторій GitHub, OAuth-клієнт Google та обліковий запис Cloudflare з планом Workers Free. Постійні дані й версії зберігає Git. Вхід Google з’являється в меню, а до налаштування пояснює, чого бракує.

1. **GitHub Pages.** Коли будете готові опублікувати локальну версію, розмістіть її в `main` репозиторію `zerothreezero/portfolio`. У **Settings → Pages → Build and deployment** виберіть **Deploy from a branch**, гілку **main**, папку **/(root)**. Перевірте відкриття `https://zerothreezero.github.io/portfolio/data/portfolio-content.json`. Це вихідна версія для першого збереження. [Налаштування Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
2. **Google.** У Google Cloud Console відкрийте **Google Auth Platform**, налаштуйте Branding та Audience, потім **Clients → Create client → Web application**. Додайте до **Authorized JavaScript origins** `https://zerothreezero.github.io`, для розробки — `http://localhost` і `http://localhost:8000`. Origin складається зі схеми, домену й порту. Скопіюйте **Client ID**. Для загальнодоступного входу налаштуйте зовнішню аудиторію та переведіть застосунок у production. Поки застосунок у Testing, додайте потрібні Google-акаунти до Test users. [Інструкція Google](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid)
3. **Токен GitHub.** У **Settings → Developer settings → Personal access tokens → Fine-grained tokens** створіть токен із терміном дії. Для **Repository access** виберіть лише `zerothreezero/portfolio`. Встановіть **Contents → Read and write**. Доступ до Metadata надається автоматично. Правила гілки мають дозволяти цьому власнику пряме оновлення `main`. [Налаштування токена](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)
4. **Cloudflare.** У файлі `worker/wrangler.jsonc` заповніть `vars.GOOGLE_CLIENT_ID`. `ALLOWED_ORIGINS` уже містить виробничий домен Pages. З папки `worker` виконайте команди нижче. Wrangler запропонує відкрити браузер для входу в Cloudflare. Перший deploy видасть точну адресу `https://portfolio-admin.…workers.dev`.

   ```sh
   npx wrangler@4 login
   npx wrangler@4 deploy
   npx wrangler@4 secret put GITHUB_TOKEN
   npx wrangler@4 secret put SESSION_SECRET
   ```

   На першому запиті секрету вставте fine-grained токен. На другому вставте випадкове значення, згенероване локально командою `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"`. В адмінці Cloudflare ці значення також можна задати у **Worker → Settings → Variables and Secrets**, тип **Secret**. [Worker Secrets](https://developers.cloudflare.com/workers/configuration/secrets/)
5. **З’єднання сайту з Worker.** У `assets/js/admin-config.js` впишіть отримані `workerOrigin` та `googleClientId`. У `index.html` допишіть **точний HTTPS-origin Worker** до `connect-src` у Content-Security-Policy. Опублікуйте ці публічні налаштування на Pages. У браузер передаються адреса Worker і публічний Client ID.
6. **Перший вхід.** Відкрийте меню **••• → Увійти через Google**. Для `thin4rtist@gmail.com` з’являться інструменти редагування. Інші підтверджені користувачі отримують лише режим перегляду. Для додаткової прив’язки у відповіді успішного запиту `/login` у вкладці Network знайдіть поле **subject**. Задайте лише його значення командою `npx wrangler@4 secret put ADMIN_SUB`. Після цього Worker перевірятиме також цей незмінний ідентифікатор Google.

Worker перевіряє підпис Google, видавця, аудиторію, строк дії, підтверджений email і точний збіг адміністратора. Сесія підписана HMAC, діє до 15 хвилин і передається в заголовку Authorization. Браузер тримає її в пам’яті вкладки. Для дострокового відкликання використовується один Durable Object із реєстром у пам’яті. Конфігурація містить потрібну для Free плану міграцію класу. Код не записує нічого в SQLite, KV або інше сховище Cloudflare. Перезапуск реєстру може вимагати повторного входу. Вихід відкликає активну сесію на сервері. API обмежено 30 запитами за хвилину на адресу клієнта в одній локації Cloudflare. [Перевірка Google ID Token](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token) · [Durable Objects Free](https://developers.cloudflare.com/durable-objects/platform/pricing/) · [Обмеження запитів](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)

## Редагування і публікація

- Увімкніть **Режим редагування** й натисніть **Редагувати** на картці. У **Керуванні роботами** доступні також приховані роботи й збережені правки до відсутніх дописів. Поля поділено на основні дані, додаткові дані, відображення та зображення.
- Кнопка **↶** біля поля видаляє його ручне перевизначення. Порожній рядок у текстовому полі може бути свідомим значенням. Поки редактор відкритий, доступні попередній перегляд та історія скасування й повтору змін.
- Для ручної роботи натисніть **Додати роботу** й виберіть PNG, JPEG або WebP. Браузер обмежує довгу сторону до 2048 px і кодує WebP до 1 MiB. Одна робота підтримує до 12 зображень. За одне збереження можна передати близько 4 MiB оптимізованих файлів. Більшу серію додавайте кількома збереженнями. Обкладинкою може бути кадр серії або окреме завантажене зображення.
- У **Керуванні колекціями** створіть назви, а в редакторі позначте потрібні колекції. У розділі відображення можна також указати статус вибраної роботи та її порядок. Приховування прибирає роботу з галереї, пошуку й статистики. JSON, історія Git та файли публічного репозиторію залишаються загальнодоступними.
- **Зберегти зміни** передає одну операцію з базовим SHA. Worker читає актуальний JSON, перевіряє зміни й створює єдиний коміт для даних та нових зображень. Гілка оновлюється без force. За конфлікту редактор залишає чернетку відкритою. Скопіюйте потрібний текст, завантажте актуальну версію та повторно внесіть правку.
- Після підтвердження GitHub зміни видно в адмінській вкладці. **Стан публікації** показує коміт і перевіряє поле `revision` у JSON, який фактично віддає GitHub Pages. Автоматична перевірка триває близько п’яти хвилин. Далі можна натиснути **Перевірити публікацію**. Якщо деплой затримався або новіший коміт випередив цей, звірте коміти й журнал Pages у GitHub Actions.
- Для **відкату** знайдіть коміт `Update portfolio content` в історії GitHub і виконайте `git revert <SHA>` у робочій копії. Після перевірки опублікуйте отриманий коміт звичним способом. Відкат відновлює також зображення, яких стосувалася операція.

## Дані та джерела

`assets/js/app.js` містить `HANDLE`, `MAX_PAGES` (10 сторінок по 100 записів), `STREAM_BATCH` (32 картки), `HIDDEN_POST_IDS`, словник перекладів та `SOFTWARE_ALIASES`. Власний допис Bluesky із зображенням автоматично з’являється під час оновлення. Репости та відповіді пропускаються. Дата в назві у форматі `YYMMDD` використовується в хронології та статистиці. Рядок `1h 25m 9212s` означає тривалість і кількість штрихів. Дублікати визначаються за послідовністю зображень.

`data/portfolio-content.json` містить версію формату, ревізію, перевизначення з ключем AT URI допису, ручні роботи з UUID та колекції. Ключ кадру базується на CID зображення, а за його відсутності — на URL. Оновлення Bluesky змінює лише вихідні дані. Зникнення допису зі стрічки не видаляє його правки з Git. Завантаження зберігаються в `assets/uploads/` під SHA-256 від вмісту. Папка з’явиться з першим завантаженням. Worker приймає лише відомий формат версії 1 та JSON розміром до 900 кБ.

## Локальний Worker і тести

1. Запустіть сайт командою `node scripts/serve.mjs`. У папці `worker` скопіюйте `.dev.vars.example` у `.dev.vars` і заповніть локальні значення. Для розробки фронтенду тимчасово вкажіть у `admin-config.js` адресу `http://localhost:8787` і свій OAuth Client ID. Для входу відкрийте саме `http://localhost:8000`; адреса має збігатися з Google Origins і `ALLOWED_ORIGINS`.
2. З папки `worker` виконайте `npx wrangler@4 dev --local`. Локальні секрети та стан Wrangler ігноруються Git. З дійсним GitHub-токеном кнопка збереження навіть на localhost записує в реальний `main`. Для перевірки без комітів використовуйте інтеграційні тести.
3. Серверні тести з кореня проєкту: `node --test worker/test/api.test.mjs`. Вони створюють тимчасову пару RSA-ключів і перевіряють авторизацію, сесії, конфлікти та помилки.
4. Браузерні тести з тестовими провайдерами: установіть Playwright для розробки командою `npm install --no-save --package-lock=false playwright`, потім `npx playwright install chromium firefox` і `node --test tests/gallery.test.cjs`. Якщо встановлено Microsoft Edge, можна задати `CHROMIUM_CHANNEL=msedge`. Реалізація Worker та редактора в тесті справжня; зовнішні мережеві відповіді та облікові дані — тестові. Для перевірки пакування Worker з його папки виконайте `npx wrangler@4 deploy --dry-run`.

Для живої перевірки після налаштування увійдіть дозволеним та іншим Google-акаунтом у різних профілях браузера. Збережіть невелику правку, звірте SHA в GitHub, дочекайтеся **Опубліковано** і відкрийте сайт у гостьовому вікні.
